# 時間序列初步分析（Time Series EDA, R）

本 skill 帶領你對一份帶時間戳記的資料，完成「初步探索性分析與前處理」，
產出的成果是：一份看得懂資料樣貌（趨勢、季節、循環、異常、缺失、平穩性）的報告，
以及一份乾淨、結構正確、可直接進入建模的資料。**本 skill 目前只負責到 EDA 與前處理為止，不含建模與預測。**

## 為什麼第一步是「先問取向」

處理時間序列有兩種常見哲學，兩者在缺失值處理與平穩性判定上會給出不同做法，
硬套會互相矛盾。所以**動手前一定要先向使用者確認取向**，再據此選擇路線。差別的根源在於：

- 一派重視**可解釋性與統計嚴謹度**（例如要寫論文、做統計諮詢、需要交代每個決策的統計依據）。
- 另一派重視**預測準確度與 pipeline 的穩健／可重現**（例如要上線、要能自動重跑、資料會持續進來）。

### 開場一定要問的問題

在讀資料之前，先問使用者（用他習慣的語言）：

> 「這次分析你比較重視哪一種？
> (A) **可解釋性與統計嚴謹度** —— 每一步都要有明確的統計依據、方便寫進報告或論文；或
> (B) **預測準確度與 pipeline 穩健性** —— 流程要能自動化、可重現、資料持續進來也不會壞。」

- 選 **(A)** → 走 **傳統統計路線（Classical）**：以單位根檢定（ADF）為主、缺失值採明確的統計插補、
  偏向 `forecast`/`tseries` 等經典工具。細節見 `references/classical-track.md`。
- 選 **(B)** → 走 **現代 fpp3 路線（Modern）**：以 tsibble 資料結構為核心、KPSS + 自動決定差分階數、
  缺失以 `fill_gaps()` 顯性化，偏向 tidyverts（tsibble/feasts/fable）。細節見 `references/modern-fpp3-track.md`。

若使用者兩者都要、或答不上來，預設走 **(B) 現代 fpp3 路線**（它與後續建模、可重現流程銜接最順），
但在報告裡對關鍵判定（尤其平穩性）補上傳統做法的對照，讓對方能自行檢視。

不要自作主張跳過這個提問——這個取向會影響後面每一步的工具與判讀方向。

## 共通流程（兩條路線都一樣的骨架）

不論走哪條路線，EDA 的骨架都是「先看資料結構 → 先畫圖 → 再分解 → 最後才談平穩性」。
fpp3 教科書反覆強調的第一原則就是：**任何分析的第一件事，是把資料畫出來**，不要一開始就跳去算檢定或造特徵。

### 貫穿全程的原則：每個結果都要「解釋意義」

不要只把圖、統計量、p 值丟出來就結束。**每做完一個步驟、每畫一張圖、每跑一個檢定，都要用一兩句話說明它的意義**，
而且盡量分成兩層：

1. **統計解讀**：這個數字／圖形在統計上代表什麼（例如「ADF p < 0.05，拒絕有單根的虛無假設，判定序列平穩」）。
2. **領域／直覺解讀**：把統計結論翻成使用者領域的白話（例如「失業率的強烈慣性，反映景氣惡化或好轉都需要數月才會完整反映在官方統計上」）。

這是本 skill 的核心價值——尤其走可解釋性路線時，報告的每個決策都要說得出「為什麼這樣做、這代表什麼」，
讓讀者或審稿人能複核，也讓非統計背景的使用者看得懂。若手上沒有足夠領域知識可解讀，就明講不確定、或反問使用者。

依序進行下列 5 個階段，每個階段做完先給使用者看結果、確認後再往下：

### 1. 資料健康檢查與結構確認

先弄清楚資料「長什麼樣」，而不是急著補值或轉換：

- **時間欄位**：哪一欄是時間？格式為何？頻率是多少（每小時 / 每日 / 每月 / 每季 / 每年）？
- **間隔是否規則**：時間戳記是不是等間隔？有沒有「跳號」的隱含缺失（該有某天卻整列不見）？
- **多序列判斷**：資料裡是不是有多條序列混在一起（不同店別、不同商品、不同測站）？
  若是，這些分組欄位在 tsibble 裡就是 **key**。
- **缺失值與異常值**：先「找出並標記」，**這一步先不要補**。補值方式取決於路線，留到第 4 階段。

> 重要原則：時間序列**不能隨機刪除列**。刪掉中間某幾筆會破壞時間間隔與落後（lag）關係，
> 讓後面的 ACF、差分、季節判讀全部失真。缺一筆就讓它顯性地缺著，之後再依路線決定怎麼補。

#### 特例：股價資料一律轉成對數報酬（log return）

只要判斷資料是**股價（或任何價格型／指數型資產序列，如指數、匯率、加密貨幣收盤價）**，
就**一律先轉成對數報酬再分析，不要直接對原始價格做 EDA 與檢定**。原始價格幾乎必然非平穩、
變異數隨價位放大，且會誤導趨勢與季節判讀；對數報酬則接近平穩、可加總、對應連續複利，是金融時序的標準做法。

```r
# 對數報酬：r_t = log(P_t) - log(P_{t-1}) = log(P_t / P_{t-1})
returns <- diff(log(price))          # 傳統 ts / 向量
# tsibble 版：
tsbl <- tsbl |> mutate(log_return = difference(log(close)))
```

轉換後的注意事項：

- 之後所有步驟（視覺化、分解、平穩性檢定、差分）都改用**對數報酬**進行；原始價格圖仍可保留一張供對照。
- 對數報酬本身通常已（近似）平穩，多半**不需要再差分**；平穩性檢定是拿來確認、而非預期一定要再差分。
- 金融報酬常見**波動聚集（volatility clustering）**：報酬本身自相關低，但報酬**平方**或**絕對值**的 ACF 會顯著。
  EDA 時可多畫一張 `ACF(報酬^2)`，並用 `FinTS::ArchTest()`（Engle's LM test）正式檢定是否存在 ARCH 效果來揭示這點。
  這是後續 **GARCH 類模型**（`fGarch::garchFit()`）的線索，但波動度建模不在本 skill 範圍。
- 若使用者明確要分析的是「價格水準」本身（例如做共整合、配對交易的長期關係），才例外保留原始價格，並在報告註明理由。

若無法從欄位名稱（close、price、adj_close…）或使用者說明判斷是不是股價，**先問使用者**再決定要不要做這個轉換。

### 2. 建立正確的時間資料結構

- 現代路線：轉成 **tsibble**（明確指定 `index` 時間索引與 `key` 分組鍵）。
- 傳統路線：用 `ts` / `zoo` / `xts` 物件，或保留 data.frame 但確保時間欄位已正確排序、對齊。

正確的資料結構是後面所有圖表與檢定的前提，先把它立好。

### 3. 視覺化探索（EDA 的重頭戲）

固定用這一組圖，從整體看到細節：

1. **時間圖 (time plot)**：看整體趨勢、季節、循環、突發異常。
2. **季節圖 (seasonal plot)**：把每個週期疊起來看季節型態。
3. **子序列圖 (subseries plot)**：分別看每個季節位置（如各月份）的平均與變化。
4. **落後圖 (lag plot)** 與 **自相關圖 (ACF / correlogram)**：看資料與過去各期的關聯強度。
5. **箱形圖 (boxplot)**：快速檢視分佈與可能的異常值（可整體看，或按月份／星期分組看季節性離群）。

判讀重點：有趨勢時 ACF 在小 lag 大且正、緩慢衰減；有季節時在季節週期倍數的 lag 出現高峰；
兩者兼具會呈現緩降且帶「扇貝狀」起伏的 ACF。

### 4. 分解與缺失值處理

- **分解**：用 **STL 分解**把序列拆成 **趨勢-循環 + 季節 + 殘差** 三成分，
  觀察各成分的樣貌與殘差是否還有結構。STL 對離群值穩健、季節型態可隨時間演化，適用面最廣。
- **缺失值 / 異常值處理**：到這一步才依路線補值（傳統：統計插補；現代：先顯性化再視需要處理）。
  補完要記錄「補了哪些、用什麼方法」，因為這會影響後續判讀。

> 補值的常見錯誤（務必避免）：**不要對根本沒有缺失的資料硬做插補**。動手前先確認缺口是否真的存在
> （例如 `sum(is.na(x))`、或 tsibble 的 `has_gaps()`），有缺才補；而且要說得出「為什麼選這個補值方法」，
> 不能因為「反正跑一下 `interpolate()` 也不會怎樣」就盲目套用——冗餘插補不會帶來改善，只會掩蓋你其實沒檢查過資料。

### 5. 平穩性與（若要接建模）差分

多數傳統模型（如 ARIMA）要求資料**平穩**（統計性質不隨時間改變）。

- **兩條路線的關鍵分歧就在這裡**：
  - 傳統：**ADF 檢定**（虛無假設 H0 = 非平穩／有單位根，p 小 → 平穩）。
  - 現代：**KPSS 檢定**（虛無假設 H0 = 平穩，p 小 → 需要差分），並用 `unitroot_ndiffs()` /
    `unitroot_nsdiffs()` **自動決定**要差分幾次。
- 兩種檢定的 H0 方向相反，**p 值的解讀完全相反**，報告裡若同時提及務必註明，避免誤讀。
- 若需差分：**先做季節差分，再視情況做一階差分**；並警惕**過度差分**會製造出實際不存在的假自相關。

### 若之後要建模：切分與時間洩露（先講清楚，避免白做）

時間序列的驗證方式和一般資料不同，這點在 EDA 交付時就要提醒使用者：

- **一律按時間順序切分訓練／測試，絕不隨機切分**。隨機打亂會讓模型「看到未來」，評估數字會虛高、上線後崩盤。
- **避免時間洩露 (time leakage)**：任何用到未來資訊的特徵（如用全序列算出的平均值、標準化參數）都必須只用訓練段的資訊計算，
  再套到測試段。EDA 階段做的轉換（log、差分、標準化）若要進模型，也要注意這條界線。
- 有明顯季節時，建模要選能吃季節的模型（SARIMA 等）；若有外生變數（如氣象資料裡的降雨、濕度），可考慮 ARIMAX／多變量延伸。

## 產出

完成後**一律交付一份 Quarto 報告的「原始檔 + 編譯結果」**，加上乾淨資料，共三樣：

1. **Quarto 原始檔 `report.qmd`**：這是可重跑的分析原稿，依上面 5 階段組織，
   每段一句話結論搭配對應圖表與程式碼區塊，最後給「資料是否平穩、建議如何處理、可否進入建模」的總結。
   請以 `assets/report-template.qmd` 為骨架填寫（YAML 標頭已設 `format: html`），R 程式碼放在 ```` ```{r} ```` 區塊裡，
   讓每張圖、每個檢定都能在編譯時實際重跑產生。
2. **編譯完成的 `report.html`**：用 Quarto 把 `.qmd` 編譯成 HTML 交付。兩種方式擇一：
   - 命令列：`quarto render report.qmd`
   - 在 R 內：`quarto::quarto_render("report.qmd")`
   編譯前確認所需套件已安裝、資料路徑正確。**若偵測到環境沒有安裝 Quarto**（例如 `quarto --version` 失敗、
   或 `quarto::quarto_path()` 找不到），**先主動詢問使用者是否要安裝 Quarto**，不要默默略過或逕自安裝：
   - 說明沒有 Quarto 就無法自動產生 `.html`，並詢問「要我協助安裝 Quarto 嗎？」
   - 若使用者同意，引導安裝（到 <https://quarto.org/docs/get-started/> 下載安裝，或視環境用套件管理器），
     安裝後再 `quarto render`；若使用者不要安裝，就只交付 `.qmd`，並說明之後可自行編譯。
3. **乾淨資料**：結構正確、缺失已處理、（若需要）已差分（或已轉對數報酬），並附上前處理的紀錄。

> 為什麼要同時給 `.qmd` 與 `.html`：`.qmd` 讓使用者能複核、修改、重跑（可重現）；`.html` 是能直接打開閱讀、分享的成品。
> 兩者一起交付，別人拿到就能「看得懂」也能「改得動」。
